Valores e binds

Todo dado do usuário entra na query como TLzNexValue e sai como bind. Nunca como texto.

Um record com tag

TLzNexValue é um record com um discriminante explícito (Kind: TLzNexValueKind) e um campo por representação. Não há Variant no meio: a conversão é decidida em tempo de compilação, o record cabe na pilha e cada leitura sabe exatamente o que tem na mão. 

V: TLzNexValue;

V := 42;                       // Kind = vkInteger
V := 'ana';                    // Kind = vkString
V := TLzNexValue.Null;         // Kind = vkNull
Writeln(V.Describe);           // NULL

Os quinze valores de TLzNexValueKind são vkUnset, vkNull, vkBoolean, vkInteger, vkInt64, vkFloat, vkCurrency, vkString, vkBytes, vkDate, vkTime, vkDateTime, vkIdentifier, vkRaw e vkSubQuery.

Conversão implícita

Seis operadores Implicit cobrem os tipos do dia a dia. É por isso que Where('id', 1) compila sem nenhuma chamada de construtor.

Data, hora, bytes, identificador, raw e subquery não têm implícito — não há tipo Pascal que os identifique sem ambiguidade (TDateTime é Double). Para esses, use o construtor nomeado.

ℹ
Raw e SubQuery recebem IInterface, não a interface final

Os dois guardam um IInterface e fazem QueryInterface na hora de compilar. É o que quebra o ciclo de uses entre LzNex.Value e LzNex.Intf. Passar uma interface que não implementa ILzNexRaw / ILzNexQuery levanta ELzNexBuilder na compilação da query, não na atribuição.

Leitura tipada

Cada leitor aceita um conjunto fechado de kinds, converte o que é convertível sem perda surpreendente, devolve o zero do tipo para Null e Unset, e levanta ELzNexBuilder no resto.

Null e Unset nunca levantam na leitura: devolvem False, 0, '' ou nil. Se a diferença entre "zero" e "ausente" importa no seu código, pergunte com IsNull antes de ler. 

TLzNexValue.FromString('x').AsDateTime;
// ELzNexBuilder: TLzNexValue: string('x') is not a date/time

TLzNexValue.Null.AsInt64;     // 0, sem exceção
TLzNexValue.FromFloat(2.6).AsInt64;   // 3 — arredonda

AsString formata data e hora de forma fixa, independente da locale: yyyy-mm-dd, hh:nn:ss e yyyy-mm-dd hh:nn:ss.

Inspecionar sem converter

property Kind: TLzNexValueKindA tag, crua.
function IsUnset: BooleanKind = vkUnset.
function IsNull: BooleanKind = vkNull.
function IsBindable: BooleanFalso para vkUnset, vkIdentifier, vkRaw e vkSubQuery — os quatro que viram texto no SQL em vez de ?.
function Text: stringO campo string interno, sem conversão: o conteúdo de vkString ou o nome de vkIdentifier. Vazio nos outros kinds.
function Ref: IInterfaceA interface guardada por Raw ou SubQuery.
function Describe: stringDescrição para log e mensagem de erro — tag e conteúdo, nunca interpolável em SQL.
 
Writeln(TLzNexValue.FromInteger(42).Describe);          // integer(42)
Writeln(TLzNexValue.FromString('ana').Describe);        // string('ana')
Writeln(TLzNexValue.Identifier('users.id').Describe);   // identifier(users.id)
Writeln(TLzNexValue.FromBytes(Buf).Describe);           // bytes(12 B)
Writeln(TLzNexValue.Unset.Describe);                    // <unset>
Writeln(TLzNexValue.Null.Describe);                     // NULL

TLzNexBindings.Describe usa isso para imprimir a lista inteira de binds: [integer(7)]. Veja inspecionar sem executar.

Unset contra Null

São estados diferentes de propósito. Unset é "nenhum valor informado" — o estado zero do record, que você obtém de graça ao declarar uma variável e não atribuir nada. Null é "o valor é NULL", uma escolha deliberada.

SituaçãoUnsetNull
IsBindablenãosim
em where / having / onlevanta ELzNexBuilder= ? com bind NULL

Db.Table('t').Where('a', TLzNexValue.Unset).ToSQL;
// ELzNexBuilder: No value given for column "a": a vkUnset arrived where a
// parameter is expected. In WHERE this is an error (in INSERT it would
// become DEFAULT).

A mensagem é longa porque o Unset em where quase sempre é variável não inicializada — e a diferença de tratamento entre where e insert é exatamente o que confunde quando o erro aparece.

⚠
Null em comparação não casa com nada

Where('a', TLzNexValue.Null) gera `a` = ? com bind NULL, e em SQL x = NULL é sempre desconhecido: a linha nunca entra no resultado. Não é bug do LzNex, é o SQL — e é por isso que existem WhereNull e WhereNotNull, que emitem is null / is not null. Veja nulidade.

Listas e pares

Quatro funções livres em LzNex.Value montam coleções de valor. Acrescente LzNex.Value ao uses se o compilador não as encontrar.

function ValueList(const AArgs: array of const): TLzNexValuesLista posicional. É o que alimenta WhereIn, OnIn e afins.
function Vals(const AArgs: array of const): TLzNexNamedValuesPares coluna/valor para insert e update, na ordem informada. Quantidade ímpar ou nome vazio levanta ELzNexBuilder.
function StringsToValues(const AItems: array of string): TLzNexValuesLista de vkString a partir de um array of string — sem passar por TVarRec.
function ValueOf(const AArg: TVarRec): TLzNexValueConverte um elemento de array of const. É o motor dos outros três.
 
L := ValueList([1, 'dois', True, 4.5]);
// L[0] vkInteger | L[1] vkString | L[2] vkBoolean | L[3] vkFloat

P := Vals(['name', 'Leonam', 'age', 38]);
// P[0].Name = 'name' | P[1].Name = 'age' — a ordem e a do SQL

Vals(['only-the-key']);
// ELzNexBuilder: Vals: expected column/value pairs, got 1 items

ValueOf mapeia nil para TLzNexValue.Null e uma interface para TLzNexValue.Raw. Ponteiro não nulo levanta — é quase sempre um @ esquecido virando argumento de query.

A restrição do array of const

array of const transporta TVarRec, e TVarRec não tem caso para record. Ou seja: você não consegue passar um TLzNexValue dentro de Vals([...]) ou ValueList([...]). A tentativa não compila, ou levanta com o VType no texto. 

// ELzNexBuilder: TLzNexValue: unsupported type in array of const (VType=..).
// Remember: a record cannot be passed in an array of const.

O contorno é montar a lista com os tipos simples e sobrescrever a posição depois. Os dois arrays são arrays de verdade, então indexar e atribuir funciona: 

V := Vals(['name', 'ana']);
V[0].Value := TLzNexValue.Raw(Db.Raw('upper(?)', ['ana']));
Db.Table('users').Insert(V);
SQL
insert into `users` (`name`) values (upper(?))

binds: ana — o do raw, na posição da coluna

Para acrescentar um par que não cabe no array of const, estenda o array:

V := Vals(['name', AName, 'batch', ABatch]);
SetLength(V, 3);
V[2].Name  := 'migration_time';
V[2].Value := TLzNexValue.FromDateTime(Now);
Db.Table('migrations').Insert(V);

Para listas de string, StringsToValues evita o assunto por completo: WhereIn('status', StringsToValues(['a', 'b'])).

Segurança

O valor nunca é interpolado no SQL. Independente do que vier dentro da string, o compilador emite ? e guarda o conteúdo na lista de binds — quem monta a instrução no banco é o driver, com parâmetro ligado. 

Db.Table('users').Where('name', '''; drop table users; --').ToSQL;
SQL
select * from `users` where `name` = ?

binds: 1 — o bind é a string inteira, ponto e vírgula incluso

O que não é bind é identificador, e identificador é escapado dobrando o caractere de quote do dialeto: 

Db.Client.WrapIdentifier('we`ird')
Saída
`we``ird`

a crase dentro do nome vira crase dobrada

Db.Client.WrapIdentifier('we"ird')
Saída
"we""ird"

a aspa dentro do nome vira aspa dobrada

WrapQualified aplica o mesmo tratamento parte por parte em nomes com ponto, então u.name sai com cada segmento quotado individualmente. * e nome vazio passam sem quote.

⚠
O que sobra fora do bind

Valor e identificador estão cobertos. O que ainda depende de você é o texto que você mesmo escreve: o template de SQL cru e o nome de coluna que você repassa de uma entrada externa. Operador está protegido por lista fechada — veja operadores aceitos.
