Erros

Toda falha previsível tem classe própria, e todas descendem de ELzNex. Dá para tratar por categoria sem casar texto de mensagem.

A hierarquia

ELzNex é a base e nunca é levantada diretamente: existe para você capturar "qualquer coisa do LzNex" numa linha. Abaixo dela, cada tipo de falha tem a sua classe — não por burocracia, mas porque a reação é diferente em cada caso. Pool esgotado pede retry; operador inválido pede correção de código; lock de migration pede esperar o outro processo.

A hierarquia é rasa: todas as classes herdam direto de ELzNex, com uma única exceção — ELzNexMigrationLock, que herda de ELzNexMigration, porque disputa de lock é um caso de migração. Todas vivem em LzNex.Exceptions.

ℹ
As mensagens dizem o que fazer

As mensagens são em inglês, como o resto do código, e são escritas para o desenvolvedor: quando existe uma saída, ela está no texto ("set LibraryLocation", "run migrate:unlock", "use LastInsertId or a SELECT afterwards"). Vale ler a mensagem inteira antes de investigar.

As classes

ELzNex = class(Exception) Base de tudo. Não é levantada diretamente. Capture-a como rede final: pega qualquer falha do LzNex e deixa passar o que não é dele.
ELzNexConfig = class(ELzNex) Configuração inválida ou incompleta, antes de qualquer SQL. Exemplos: Connect sem configuração; dialeto não registrado (Dialect "pg" is not registered. Available: mysql, mariadb. — a unit do dialeto ficou fora do uses); Pool min (5) is greater than max (3); JSON malformado; ambiente que não existe no arquivo; valor que deveria ser inteiro e não é.
ELzNexConnection = class(ELzNex) A conexão física. Falha ao abrir (Could not open connection to mysql:3306/lznex: …, com o lembrete de LibraryLocation), uso de conexão já fechada (Connection already closed) e uso de empréstimo já devolvido ao pool (This leased connection was already returned to the pool and cannot be used anymore).
ELzNexPool = class(ELzNex) Dois casos, os dois descritos em Pool e threads: pool esgotado depois do AcquireTimeout (Pool exhausted: 8 connections in total (max 8), 8 in use. …) e Acquire depois do Shutdown.
ELzNexBuilder = class(ELzNex) A cadeia de chamadas está errada — é bug no código que monta a query, e o SQL nunca é gerado. Operador fora da lista fechada; WhereClose sem WhereOpen; ToSQL com grupo aberto; FromSub/JoinSub sem alias; Vals com número ímpar de itens; On* antes de qualquer Join; TLzNexValue lido como tipo que não é o dele; query criada com NewQuery (que só monta SQL) tentando executar.
ELzNexCompile = class(ELzNex) O builder está coerente, mas o dialeto não dá conta. RETURNING is not supported by mysql. Use LastInsertId or a SELECT afterwards.; DISTINCT ON is not supported by mysql. Use plain Distinct or group by.; Section "limit" is not valid in delete on dialect postgresql.; UPDATE without SET: no column to update.; subquery no from sem alias.
ELzNexQuery = class(ELzNex)
constructor CreateFmt(const AMessage, ASQL: string)
property SQL: string read FSQL 		O SQL chegou ao banco e o banco recusou — ou o bind não era bindável. É a única classe que carrega o SQL: E.SQL devolve o texto exato que foi enviado, e a mensagem já traz esse texto numa segunda linha prefixada por SQL: . Exemplos: Failed to prepare: …, Failed to execute: …, Query failed: …, Bind 2 is not a bindable value: …, The query did not return a resultset, Cursor already released.
ELzNexSchema = class(ELzNex) Definição de tabela incoerente, detectada ao compilar o DDL: Index without columns on table "users"., enum without items in MySQL DDL. Veja Schema builder.
ELzNexMigration = class(ELzNex) Histórico ou registro de migrations inconsistente: id duplicado entre duas migrations (com as duas classes na mensagem); Migration "x" does not exist in any source.; Migration "x" is already applied.; Migration "x" is not applied.; migration aplicada que não existe mais em fonte nenhuma (arquivo renomeado, ou unit fora do agregador e não linkada); No migration source registered…; e a falha de uma migration, embrulhada como Migration <nome> failed: <erro original>.
ELzNexMigrationLock = class(ELzNexMigration) A tabela de lock já está tomada: outro processo está migrando agora, ou um processo morreu segurando o lock. A mensagem termina mandando rodar migrate:unlock. Por herdar de ELzNexMigration, capture-a antes da mãe. No CLI ela tem exit code próprio (3) justamente para o script distinguir disputa de falha.
ELzNexTransaction = class(ELzNex) Uso errado do escopo transacional: Commit ou Rollback em transação já concluída (…on an already completed transaction (level 1). Commit and Rollback end the transaction; …); concluir a externa com savepoint interno aberto (savepoints têm de fechar em ordem LIFO); Transaction already released; nível de isolamento que o banco recusou. Tratando

Do mais específico para o mais genérico — o FPC avalia os on na ordem escrita, e um on E: ELzNex no topo engoliria todos os outros. 

try
  Db.Table('users').Insert(Vals(['email', Email]));
except
  on E: ELzNexQuery do
  begin
    // o banco recusou: E.SQL tem o texto exato que foi enviado
    Log('SQL recusado: ' + E.SQL);
    Log('motivo: ' + E.Message);
    raise;
  end;
  on E: ELzNexBuilder do
    // bug nosso: a query nem chegou a ser gerada
    Log('query mal montada: ' + E.Message);
  on E: ELzNex do
    // qualquer outra falha do LzNex (config, pool, conexao, transacao...)
    Log('LzNex (' + E.ClassName + '): ' + E.Message);
end;

E.SQL é o que separa "o banco recusou" de "não sei o que foi enviado". A mensagem também contém o SQL, mas na propriedade ele vem limpo, pronto para log estruturado ou para colar num cliente e reproduzir: 

ELzNexQuery: Failed to execute: Duplicate entry 'ana@ex.com' for key 'users.email_unique'
SQL: insert into `users` (`email`) values (?)

Num servidor HTTP, o par útil é ELzNexQuery (vira 4xx ou 5xx, dependendo de ser violação de constraint ou falha de infra) e ELzNexPool (vira 503: o banco não está indisponível, o pool é que não tem conexão livre agora — o cliente pode tentar de novo).

ELzNexBuilder contra ELzNexCompile

As duas levantam antes de o SQL sair, mas significam coisas opostas, e confundi-las custa tempo de depuração.

ELzNexBuilderELzNexCompile
o que aconteceu A cadeia de chamadas não faz sentido em SQL nenhum. A cadeia é coerente, mas este banco não tem o recurso.
o que fazer Corrigir o código: falta um WhereClose, um alias, um argumento. Escrever esse trecho de outro jeito para este banco — a mensagem costuma dizer qual.
muda de dialeto? Não. É erro em qualquer um. Sim. O mesmo código passa no outro dialeto.
exemplo WhereClose sem WhereOpen; operador fora da lista fechada. Returning em MySQL; DistinctOn em MySQL; limit em delete no PostgreSQL. 
// ELzNexBuilder: errado em qualquer banco
Db.Table('t').Where('a', '; drop table users; --', 1);
// Operator "; drop table users; --" is not allowed. The list is closed on purpose...

// ELzNexCompile: correto em PostgreSQL, impossivel em MySQL
Db.Table('users').Returning(['id']).Insert(Vals(['name', 'Ana']));
// Returning: dialect "mysql" does not support RETURNING

Na prática: ELzNexCompile quase sempre quer dizer "troque este trecho por InsertGetId, por Distinct simples, por group by, ou por um segundo select". A tabela de capacidades em Dialetos lista cada recurso e a alternativa em cada banco.

⚠
Capacidade é checada cedo quando dá

Returning levanta já na chamada do método, não na compilação, porque a capacidade dá para consultar naquele instante. Outros casos, como seção proibida no verbo, só são conhecidos quando a árvore está completa e levantam no ToSQL. Em ambos a classe é ELzNexCompile — o quando muda, o significado não.
