Agrupar, ordenar e paginar

GroupBy, Having, OrderBy, paginação e travamento de linha.

Group by e having

Db.Table('orders').Select(['user_id']).GroupBy(['user_id']).Having('total', '>', 100)
Db.Table('users').GroupBy(['dept']).GroupByRaw('year(??)', ['created_at'])
Db.Table('users').HavingBetween('n', 1, 9)
Db.Table('users').HavingRaw('exists (select 1)', [])
Db.Table('users').HavingOpen.Having('a', '>', 1).OrHaving('b', '>', 2).HavingClose
SQL
select `user_id` from `orders` group by `user_id` having `total` > ?
select * from `users` group by `dept`, year(`created_at`)
select * from `users` having `n` between ? and ?
select * from `users` having exists (select 1)
select * from `users` having (`a` > ? or `b` > ?)

Having exige operador explícito — não há overload de dois argumentos, porque having quase nunca é igualdade. Há também HavingIn, HavingNull e HavingNotNull.

Order by

Db.Table('t').OrderBy('name')                     // asc e o default
Db.Table('t').OrderBy('name', odDesc)
Db.Table('t').OrderByDesc('name')
Db.Table('t').OrderBy('name').OrderBy('id', odDesc)
Db.Table('users').OrderByRaw('field(??, ?)', ['s', 'a'])
SQL
select * from `t` order by `name` asc
select * from `t` order by `name` desc
select * from `t` order by `name` desc
select * from `t` order by `name` asc, `id` desc
select * from `users` order by field(`s`, ?) asc

Posição dos NULL

O terceiro overload aceita nlFirst ou nlLast. Onde o banco tem nulls first/last nativo, sai nativo; onde não tem, o LzNex emula ordenando antes pela flag de nulidade — o resultado é o mesmo, o texto não. 

Db.Table('t').OrderBy('name', odAsc, nlLast)
Db.Table('t').OrderBy('due', odDesc, nlFirst)
SQL
select * from `t` order by (`name` is null) asc, `name` asc
select * from `t` order by (`due` is null) desc, `due` desc
Db.Table('t').OrderBy('name', odAsc, nlLast)
Db.Table('t').OrderBy('name', odDesc, nlFirst)
SQL
select * from "t" order by "name" asc nulls last
select * from "t" order by "name" desc nulls first

Paginação

Db.Table('t').Limit(10).Offset(20)
Db.Table('t').Page(3, 10)         // pagina 1-based: limit 10 offset 20
SQL
select * from `t` limit ? offset ?
select * from `t` limit ? offset ?

Page valida: página menor que 1 ou tamanho menor que 1 levanta ELzNexBuilder.

Offset sem Limit

select * from `t` limit 18446744073709551615 offset ?

o MySQL exige LIMIT junto do OFFSET; o teto é o máximo de 64 bits

select * from "t" offset ?

o Postgres aceita OFFSET sozinho: nada de limite artificial

Travamento de linha

Db.Table('users').Where('id', 1).ForUpdate
Db.Table('users').ForUpdate.SkipLocked
Db.Table('users').ForShare.NoWait
SQL
select * from `users` where `id` = ? for update
select * from `users` for update skip locked
select * from `users` for share nowait

Lock só faz sentido dentro de transação — fora dela o banco solta a trava no fim do comando. Veja Transações.
