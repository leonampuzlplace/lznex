Joins

Join devolve ILzNexJoin, que herda ILzNexQuery: dá para encadear as cláusulas On* e continuar a query na mesma expressão. 

Db.Table('posts')
  .Join('users').OnColumns('posts.user_id', '=', 'users.id')
  .LeftJoin('tags').OnColumns('tags.post_id', '=', 'posts.id')
  .Where('posts.published', True)
  .Get;
SQL
select * from `posts`
  inner join `users` on `posts`.`user_id` = `users`.`id`
  left join `tags` on `tags`.`post_id` = `posts`.`id`
 where `posts`.`published` = ?

OnColumns ou OnValue

⚠
Dois métodos, não um

OnColumns compara identificadores (sem bind) e OnValue compara com valor (com bind). Um método único para os dois casos teria que adivinhar, e on('tags.active', '=', True) acabaria virando comparação com uma coluna chamada True — erro que não aparece nem na compilação nem no resultado. 

Db.Table('posts').LeftJoin('tags').OnValue('tags.active', '=', True)
SQL
select * from `posts` left join `tags` on `tags`.`active` = ?

binds: True

Tipos de join

Db.Table('users').Join('posts')           // ou InnerJoin
Db.Table('users').LeftJoin('posts')
Db.Table('users').LeftOuterJoin('a')
Db.Table('users').RightJoin('b')
Db.Table('users').RightOuterJoin('tags')
Db.Table('users').FullOuterJoin('logs')
Db.Table('users').CrossJoin('logs')
Db.Table('users').JoinAs('posts', 'p').OnColumns('p.user_id', '=', 'users.id')
SQL (trecho)
inner join `posts`
left join `posts`
left outer join `a`
right join `b`
right outer join `tags`
full outer join `logs`
cross join `logs`
left join `posts` as `p` on `p`.`user_id` = `users`.`id`

Cláusulas ON compostas

Db.Table('users').Join('posts')
  .OnColumns('posts.user_id', '=', 'users.id')
  .AndOnValue('posts.status', '=', 'live')
  .OrOnColumns('posts.author_id', '=', 'users.id');

Db.Table('users').Join('posts').OnIn('posts.status', StringsToValues(['a', 'b']));
Db.Table('users').LeftJoin('posts').OnNotNull('posts.deleted_at');
Db.Table('users').Join('posts').OnBetween('posts.score', 1, 10);
Db.Table('users').Join('posts').OnRaw('1 = ?', [1]);
Db.Table('users').Join('posts').Using(['user_id', 'tenant_id']);
SQL (trecho do ON)
on `posts`.`user_id` = `users`.`id` and `posts`.`status` = ? or `posts`.`author_id` = `users`.`id`
on `posts`.`status` in (?, ?)
on `posts`.`deleted_at` is not null
on `posts`.`score` between ? and ?
on 1 = ?
using (`user_id`, `tenant_id`)

Subquery e SQL cru

Sub := Db.Query.Table('p').Select(['id']).Where('y', 2);
Db.Table('users').JoinSub(Sub, 'q').OnColumns('q.id', '=', 'users.id');

Db.Table('users').JoinRaw('straight_join `x` on 1 = ?', [1]);
SQL
select * from `users` left join (select `id` from `p` where `y` = ?) as `q` on `q`.`id` = `users`.`id`
select * from `users` straight_join `x` on 1 = ?

JoinRaw devolve ILzNexQuery, não ILzNexJoin: o texto cru já traz a cláusula ON inteira, então não há o que encadear.
