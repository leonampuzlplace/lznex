Union, CTE e hint

Operadores de conjunto, expressões de tabela comuns e dicas para o otimizador.

Union

Old := Db.Query.Table('old').Where('y', 3);

Db.Table('users').UnionAll(Old)
Db.Table('users').Union(Db.Query.Table('old'))
Db.Table('users').Intersect(A).Except_(B)
Db.Table('users').Union(A).OrderBy('id')
SQL
select * from `users` union all (select * from `old` where `y` = ?)
select * from `users` union (select * from `old`)
select * from `users` intersect (select 1) except (select 2)
select * from `users` union (select 1) order by `id` asc

Except_ leva sublinhado porque except é palavra reservada do Pascal. O order by vale para o conjunto inteiro e por isso sai depois do union — a ordem das seções é do dialeto, não da ordem de chamada.

⚠
Firebird não tem intersect nem except

Nem no 3, nem no 5. Intersect e Except_ levantam ELzNexCompile ali, com a mensagem sugerindo a reescrita: WhereInSub para a interseção, WhereNotExists para a diferença. Union e UnionAll funcionam nos quatro bancos.

CTE

Recent := Db.Query.Table('logs').Where('d', '>', '2024-01-01');

Db.Table('users').With_('recent', Recent)
Db.Table('users').WithRecursive('tree', T).With_('other', O)
SQL
with `recent` as (select * from `logs` where `d` > ?) select * from `users`
with recursive `tree` as (select 1), `other` as (select 2) select * from `users`

Hint

Db.Table('users').HintComment('max_execution_time(1000)')
SQL
select /*+ max_execution_time(1000) */ * from `users`
⚠
Hint é validado

Um hint que contenha */ levanta ELzNexBuilder: fechar o comentário por dentro permitiria emendar SQL arbitrário depois dele.
