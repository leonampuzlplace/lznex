Insert, upsert e update

Vals(['coluna', valor, …]) monta os pares, e a ordem informada é a ordem do SQL.

Insert

N  := Db.Table('users').Insert(Vals(['name', 'ana', 'age', 30]));
Id := Db.Table('users').InsertGetId(Vals(['name', 'Leonam', 'email', 'l@x.com']));
SQL
insert into `users` (`name`, `age`) values (?, ?)

binds: ana | 30 · Insert devolve linhas afetadas; InsertGetId, o id gerado

ℹ
InsertGetId e o pool

O InsertGetId faz o insert e lê LastInsertId na mesma conexão. Com pool, duas chamadas independentes poderiam cair em conexões diferentes e devolver o id de outra thread. Isso está testado com 8 threads, cada id conferido contra a linha daquela thread.

InsertMany

Várias linhas num único comando. Coluna ausente em uma das linhas vira default, não NULL — é o vkUnset de TLzNexValue em ação. Coluna que aparece só numa linha posterior entra no fim da lista de colunas. 

Db.Table('users').InsertMany([
  Vals(['name', 'ana', 'age', 30]),
  Vals(['name', 'bob'])
]);

Db.Table('users').InsertMany([
  Vals(['name', 'ana']),
  Vals(['name', 'bob', 'age', 40])
]);
SQL
insert into `users` (`name`, `age`) values (?, ?), (?, default)
insert into `users` (`name`, `age`) values (?, default), (?, ?)

binds: ana | 30 | bob · ana | bob | 40

Valor cru numa coluna do insert:

V := Vals(['name', 'ana']);
V[0].Value := TLzNexValue.Raw(Db.Raw('upper(?)', ['ana']));
Db.Table('users').Insert(V);
SQL
insert into `users` (`name`) values (upper(?))

Returning

Db.Table('users').Returning(['id']);
// ELzNexCompile: MySQL nao suporta RETURNING. Use InsertGetId.
Db.Table('users').Returning(['id', 'created_at']).Insert(Vals(['name', 'ana']));
Db.Table('users').Where('id', 7).Returning(['id']).Update(Vals(['name', 'x']));
Db.Table('users').Where('id', 7).Returning(['id']).Delete;
SQL
insert into "users" ("name") values (?) returning "id", "created_at"
update "users" set "name" = ? where "id" = ? returning "id"
delete from "users" where "id" = ? returning "id"

Upsert

OnConflict devolve ILzNexOnConflict, que só tem Ignore, Merge e MergeValues. Esquecer de completar a cláusula não compila. 

Db.Table('users').OnConflict(['email']).Ignore
  .Insert(Vals(['name', 'ana']));

Db.Table('users').OnConflict(['email']).Merge
  .Insert(Vals(['name', 'ana', 'age', 30]));

Db.Table('users').OnConflict(['email']).Merge(['age'])
  .Insert(Vals(['name', 'ana', 'age', 30]));

Db.Table('users').OnConflict(['email']).MergeValues(Vals(['age', 99]))
  .Insert(Vals(['name', 'ana', 'age', 30]));
SQL
insert ignore into `users` (`name`) values (?)
insert into `users` (`name`, `age`) values (?, ?) on duplicate key update `name` = values(`name`), `age` = values(`age`)
insert into `users` (`name`, `age`) values (?, ?) on duplicate key update `age` = values(`age`)
insert into `users` (`name`, `age`) values (?, ?) on duplicate key update `age` = ?

no insert ignore a coluna de conflito não aparece: o MySQL resolve no verbo

Db.Table('users').OnConflict(['email']).Ignore
  .Insert(Vals(['name', 'ana']));

Db.Table('users').OnConflict([]).Ignore
  .Insert(Vals(['name', 'ana']));

Db.Table('users').OnConflict(['email']).Merge
  .Insert(Vals(['name', 'ana', 'age', 30]));

Db.Table('users').OnConflict(['email']).MergeValues(Vals(['name', 'fixed']))
  .Insert(Vals(['name', 'ana']));
SQL
insert into "users" ("name") values (?) on conflict ("email") do nothing
insert into "users" ("name") values (?) on conflict do nothing
insert into "users" ("name", "age") values (?, ?) on conflict ("email") do update set "name" = excluded."name", "age" = excluded."age"
insert into "users" ("name") values (?) on conflict ("email") do update set "name" = ?

no Postgres, do update exige a coluna de conflito: Merge sem OnConflict([...]) levanta ELzNexCompile

Em MergeValues, um valor TLzNexValue.Unset reaproveita o valor que veio no insert em vez de gerar bind — útil para misturar colunas fixas e colunas copiadas.

Update, increment e delete

N := Db.Table('users').Where('id', 7).Update(Vals(['name', 'x', 'email', 'y']));
Db.Table('users').Where('id', 7).Increment('hits');          // +1
Db.Table('users').Increment('hits', 10);
Db.Table('users').Decrement('stock', 2);
N := Db.Table('users').Where('id', 3).Delete;
Db.Table('logs').Truncate;
SQL
update `users` set `name` = ?, `email` = ? where `id` = ?
update `users` set `hits` = `hits` + ? where `id` = ?
update `users` set `hits` = `hits` + ?
update `users` set `stock` = `stock` + ?
delete from `users` where `id` = ?
truncate `logs`

o bind de Decrement é -2: o delta negativo vai no valor, não no SQL

Increment e Decrement geram col = col + ? — a soma acontece no banco, sem o ciclo ler-somar-gravar e sem a corrida que ele traz. Update sem colunas levanta ELzNexBuilder; AST de update sem set levanta ELzNexCompile.

Particularidades por dialeto

-- update com join, alias e limit
update `users` as `u` inner join `tenants` as `t` on `t`.`id` = `u`.`tenant_id` set `name` = ? limit ?

-- delete com limit
delete from `users` where `id` = ? limit ?

-- delete com join repete o alvo antes do from
delete `u` from `users` as `u` inner join `tenants` as `t` on `t`.`id` = `u`.`tenant_id`

-- truncate sem reiniciar a sequencia
truncate `users`
-- limit em delete nao e aceito: levanta ELzNexCompile mencionando 'limit'

-- truncate reinicia a identidade
truncate "users" restart identity
