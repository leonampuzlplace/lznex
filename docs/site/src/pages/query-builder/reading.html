Executar e ler

Os terminais de leitura. Cada um executa e devolve algo pronto para usar.

TerminalO que faz
function Get: ILzNexResultExecuta o select e devolve o cursor forward-only.
function First: ILzNexRowPrimeira linha materializada, ou nil. Acrescenta limit 1 se não houver limite.
function FirstOrFail: ILzNexRowComo First, mas levanta ELzNexQuery em vez de devolver nil.
function Sole: ILzNexRowExige exatamente uma linha: levanta se nenhuma, e levanta se mais de uma. Pede limit 2.
function Value(const AColumn: string): TLzNexValueTroca a lista de colunas pela informada e devolve o escalar da primeira linha. Sem linha: Null.
function Scalar: TLzNexValuePrimeira coluna da primeira linha, sem mexer no select.
function Pluck(const AColumn: string): TLzNexValuesUma coluna de todas as linhas, como array.
function Exists: Booleanlimit 1 + existe linha?
function DoesntExist: BooleanO complemento de Exists, para o if não precisar de not.
function Count: Int64count(*) já convertido.
function Aggregate(const AAgg: TLzNexAggregate; const AColumn: string): TLzNexValueagCount, agMin, agMax, agSum, agAvg.
 
Rows  := Db.Table('users').Where('active', True).Get;
Row   := Db.Table('users').Where('id', 7).First;

SQL de cada um
select * from `users` where `active` = ?
select * from `users` where `id` = ? limit ?
select `name` from `users` where `id` = ? limit ?
select count(*) from `users` where `active` = ? limit ?
select `id` from `users`
select avg(`total`) from `orders` limit ?
select * from `users` where `email` = ? limit ?

O limit ? em First, Value, Count e Aggregate não é desperdício: todos leem uma linha só, e o limite evita que o banco materialize o resto.

Quando "zero linha" é erro

First devolve nil e obriga quem chamou a testar; é o certo numa busca. Quando a ausência da linha é um defeito — o id veio de uma chave estrangeira, por exemplo —, FirstOrFail transforma isso em exceção com o SQL anexado. E Sole vai além: afirma que o filtro identifica uma linha, e levanta também quando vêm duas. 

Row := Db.Table('users').Where('id', 7).FirstOrFail;       // levanta se nao existe
Row := Db.Table('users').Where('email', AMail).Sole;       // levanta se 0 ou se 2+
if Db.Table('users').Where('email', AMail).DoesntExist then
  Db.Table('users').Insert(Vals(['email', AMail]));
SQL
select * from `users` where `id` = ? limit ?
select * from `users` where `email` = ? limit ?
select * from `users` where `email` = ? limit ?

Sole pede limit 2: duas linhas bastam para saber que há mais de uma

Para ler muitas linhas sem carregar tudo na memória, nenhum destes serve: veja Chunk e Each. Para janelas de tela, veja Paginação.

Agregados

Agregado com distinct e alias sai assim:

select count(distinct `email`) as `c`, sum(`total`) as `t` from `users`

Agregado sem coluna vira count(*). Count é atalho para Aggregate(agCount, '*').AsInt64.
