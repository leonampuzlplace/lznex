Where e grupos

Valor entra sempre como bind. Números, strings e booleanos convertem sozinhos.

Comparação

Dois overloads: sem operador (assume =) e com operador explícito.

Db.Table('users').Where('id', 1)
Db.Table('users').Where('age', '>=', 18)
Db.Table('users').Where('a', 1).Where('b', 'x')        // and
Db.Table('t').Where('a', 1).OrWhere('b', 2).Where('c', 3)
Db.Table('t').WhereNot('a', 1)
SQL
select * from `users` where `id` = ?
select * from `users` where `age` >= ?
select * from `users` where `a` = ? and `b` = ?
select * from `t` where `a` = ? or `b` = ? and `c` = ?
select * from `t` where not `a` = ?
ℹ
O OR não contamina o resto

O conector é parâmetro de cada statement, não um estado do builder: OrWhere afeta só o predicado que ele introduz, como mostra o quarto exemplo acima.

Operadores aceitos

A lista é fechada. Operador fora dela levanta ELzNexBuilder — é o que fecha a porta para injeção via operador vindo de entrada do usuário.

Db.Table('t').Where('a', '; drop table users; --', 1);
// ELzNexBuilder: operador fora da lista aceita

Coluna contra coluna

Db.Table('t').WhereColumn('a.id', '=', 'b.a_id')
SQL
select * from `t` where `a`.`id` = `b`.`a_id`

binds: nenhum — os dois lados são identificadores

Listas

Db.Table('t').WhereIn('id', ValueList([1, 2, 3]))
Db.Table('t').WhereNotIn('id', ValueList([1, 2]))
Db.Table('t').WhereIn('id', nil)       // lista vazia
Db.Table('t').WhereNotIn('id', nil)
SQL
select * from `t` where `id` in (?, ?, ?)
select * from `t` where `id` not in (?, ?)
select * from `t` where 1 = 0
select * from `t` where 1 = 1

Lista vazia vira 1 = 0 (e not in vazio vira 1 = 1) por duas razões: in () não é SQL válido, e um filtro sem candidatos não deve casar com nada. 

Sub := Db.Query.Table('t').Select(['id']).Where('z', 9);
Db.Table('users').Where('a', 1).WhereInSub('id', Sub);
SQL
select * from `users` where `a` = ? and `id` in (select `id` from `t` where `z` = ?)

binds: 1 | 9 — na ordem do texto

Nulidade, faixa e padrão

Db.Table('t').WhereNull('a')
Db.Table('t').WhereNotNull('a')
Db.Table('t').WhereBetween('age', 18, 65)
Db.Table('t').WhereNotBetween('age', 18, 65)
Db.Table('t').WhereLike('name', '%jo%')
Db.Table('t').WhereNotLike('name', '%jo%')
SQL
select * from `t` where `a` is null
select * from `t` where `a` is not null
select * from `t` where `age` between ? and ?
select * from `t` where `age` not between ? and ?
select * from `t` where `name` like ?
select * from `t` where `name` not like ?

WhereILike usa ilike nativo onde existe. Em MySQL, onde a comparação já é insensível a caixa por collation, cai em like. 

select * from `users` where `name` like ?
select * from "users" where "name" ilike ?

Exists e SQL cru

Sub := Db.Query.Table('p').SelectRaw('1', []).WhereColumn('p.u', '=', 'users.id');
Db.Table('users').WhereExists(Sub);
Db.Table('users').WhereNotExists(Sub);

Db.Table('t').WhereRaw('age > ? and active = ?', [18, True]);
Db.Table('users').WhereRaw('json_extract(??, ?) = ?', ['d', '$.a', 5]);
SQL
select * from `users` where exists (select 1 from `p` where `p`.`u` = `users`.`id`)
select * from `users` where not exists (select 1 from `p` where `p`.`u` = `users`.`id`)
select * from `t` where age > ? and active = ?
select * from `users` where json_extract(`d`, ?) = ?

binds: 18 | True · $.a | 5

Veja SQL cru para a gramática completa de ?, ?? e :nome.

Grupos de predicado

Como o FPC 3.2.2 não tem função anônima, o parêntese é aberto e fechado explicitamente. O builder mantém uma pilha de grupos. 

Db.Table('users')
  .Where('active', True)
  .WhereOpen
    .Where('role', 'admin')
    .OrWhere('role', 'owner')
  .WhereClose
SQL
select * from `users` where `active` = ? and (`role` = ? or `role` = ?)

binds: True | admin | owner

Grupos aninham, e um grupo pode abrir a cláusula:

Db.Table('t').Where('a', 1)
  .WhereOpen
    .Where('b', 2)
    .OrWhereOpen.Where('c', 3).Where('d', 4).WhereClose
  .WhereClose;

Db.Table('t')
  .WhereOpen.Where('a', 1).OrWhere('b', 2).WhereClose
  .Where('c', 3);
SQL
select * from `t` where `a` = ? and (`b` = ? or (`c` = ? and `d` = ?))
select * from `t` where (`a` = ? or `b` = ?) and `c` = ?
MétodoAbre

HavingOpen / HavingCloseo mesmo, em having
⚠
Grupo mal formado levanta

ToSQL exige OpenGroupCount = 0: grupo aberto e não fechado levanta ELzNexBuilder. WhereClose sem WhereOpen correspondente levanta na hora da chamada. Nenhum dos dois casos chega ao banco como SQL quebrado.
