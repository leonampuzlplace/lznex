Log de queries

ILzNexLogger recebe cada query executada, com os binds e o tempo. O logger de console pronto escreve em stdout com flush. 

uses LzNex, LzNex.Config;

Db := Connect(NewConfig
  .Client('mysql').Host('mysql').Database('app').User('root')
  .Logger(TLzNexConsoleLogger.New(True)));   // False silencia so LogQuery
2026-10-24 18:31:07 [lznex] query (3ms) select * from `users` where `id` = ?  binds=[integer(7)]
2026-10-24 18:31:07 [lznex] warn  MySQL commits DDL implicitly: rollback will not undo it
2026-10-24 18:31:08 [lznex] error Duplicate entry 'l@x.com' for key 'users_email_unique'
  sql: insert into `users` (`email`) values (?)
ℹ
Por que o flush importa

stdout redirecionado — container, pipe, CI — é bufferizado. Sem flush, o log de um processo que morre no meio simplesmente desaparece. O logger de console e o CLI já dão flush a cada linha.

O que é registrado, e quando

Quem chama o logger é a camada de conexão: todo Execute, Query e ExecuteScript é cronometrado e passa por LogQuery ao terminar; se levantar, passa por LogError antes de a exceção subir. O pool repassa o logger da configuração a cada conexão que abre, então nada precisa ser ligado query por query.

ChamadaQuandoO que chega
LogQuery depois de cada execução concluída o SQL com os ? no lugar (nunca interpolado), as bindings cruas e o tempo em ms
LogError quando o banco recusa o mesmo SQL e a mensagem do driver; a exceção continua subindo
LogInfo Query.Dump, migrations e seeds texto pronto
LogWarning situações como DDL não transacional no MySQL texto pronto
ℹ
O tempo medido é o da ida ao banco, não o da leitura das linhas

Num Query o cronômetro para quando o cursor volta — e o cursor volta antes de as linhas serem consumidas. Uma query que devolve dez mil linhas pode aparecer com 2ms no log e levar bem mais que isso para ser percorrida. Para medir o consumo, meça em volta do seu laço.

Exceção lançada pelo logger é engolida de propósito: log quebrado não pode derrubar quem só queria executar uma query.

Logger próprio

type
  TMyLogger = class(TInterfacedObject, ILzNexLogger)
  public
    procedure LogQuery(const ASQL: string; const ABindings: TLzNexBindings;
      const AElapsedMs: Int64);
    procedure LogError(const ASQL: string; const AError: string);
    procedure LogWarning(const AMessage: string);
    procedure LogInfo(const AMessage: string);
  end;

ABindings.Describe devolve os valores com a tag de cada um (integer(7), string('ana')) — é descrição para humano, nunca SQL executável. O mesmo vale para Query.ToSQLString e Client.EscapeForLog: existem para log, e não devem ser enviados ao banco.
