Instalação

Instalável por Boss em qualquer projeto Lazarus, inclusive os que usam Horse.

Pelo Boss

// boss.json do seu projeto
{
  "dependencies": {
    "github.com/leonampuzlplace/lznex": "^1.0.0"
  }
}
boss install

O ZeosLib vem junto, como dependência transitiva. O Boss cria as pastas em modules/<host>_<org>_<repo> (pontos e barras viram _), e é esse nome que entra nos unit paths do seu .lpi.

ℹ
Coordenada

O boss.json do repositório ainda aponta para github.com/CHANGEME/lznex e github.com/CHANGEME/zeoslib. Enquanto o pacote não for publicado, os Dockerfiles montam modules/ com o mesmo layout que o Boss produziria. O fork do Zeos precisa ter boss.json: o Boss aborta se uma dependência não tiver manifesto.

O uses mínimo

uses
  LzNex,                 // a facade: Connect, NewConfig, ILzNex, ILzNexQuery...
  LzNex.Client.MySQL;    // o dialeto. Sem esta linha, Connect levanta.
⚠
Armadilha estrutural do Pascal

O linker do FPC descarta unit que ninguém referencia em uses. Unit descartada não executa seu initialization — e é ali que o dialeto se registra no registry. O sintoma é Requested database driver was not found em tempo de execução, sem erro de compilação. A mesma regra vale para migrations e seeds escritas em Pascal.

Programa com threads

Em Unix, programa que usa threads precisa de cthreads no início do uses do .lpr — antes de qualquer outra unit: 

uses
  {$IFDEF UNIX}{$IFDEF UseCThreads}
  cthreads,
  {$ENDIF}{$ENDIF}
  SysUtils, Horse, LzNex, LzNex.Client.MySQL;

Pela IDE

O lznex.lpk na raiz do repositório é o caminho para quem usa a IDE do Lazarus: abra o pacote, compile e adicione como dependência do seu projeto. O ZeosLib precisa estar instalado separadamente nesse caminho.
