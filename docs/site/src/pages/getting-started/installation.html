Instalação

Pela IDE ou por Boss, em qualquer projeto Lazarus — inclusive os que usam Horse.

Pré-requisito: ZeosLib 8

O LzNex não traz o Zeos junto: quem instala é que o fornece, de uma fonte só. Vale o pacote zdbc instalado na IDE, a coordenada de um fork do Zeos com boss.json no seu próprio boss.json (o repositório oficial não tem manifesto, e o Boss aborta sem ele) ou um clone seu no unit path.

⚠
Duas cópias do Zeos não convivem

É por isso que o pacote não vendoriza o Zeos. Se o LzNex trouxesse a sua própria cópia em modules/, quem já tem o Zeos instalado na IDE ficaria com as mesmas units em dois caminhos — e o build para em Duplicate unit ou num .ppu incompatível, não em algo que pareça com a causa.

Pela IDE

O lznex.lpk na raiz do repositório é o caminho de quem usa a IDE do Lazarus: abra o pacote, compile e adicione como dependência do seu projeto. O .lpk requer o pacote zdbc ≥ 8, então a IDE resolve pelo Zeos que você já tem instalado — nada é duplicado. É o caminho mais curto para quem já roda Zeos na IDE.

Pelo Boss

// boss.json do seu projeto
{
  "dependencies": {
    "github.com/leonampuzlplace/lznex": "^1.0.0"
  }
}
boss install

O Boss cria as pastas em modules/<host>_<org>_<repo> (pontos e barras viram _), e é esse nome que entra nos unit paths do seu .lpi. O Zeos não aparece aí: ele não é dependência do pacote.

De onde sai a versão

O Boss usa versionamento semântico e resolve a dependência pelas tags do repositório, no formato vX.Y.Z. Quem publica essas tags é a GitHub Action: toda entrega em production com CI verde cria a tag seguinte e sincroniza a versão do boss.json com ela. Os intervalos aceitos no seu boss.json são os de sempre:

Escrito assimAceita
^1.0.4 · 1 · 1.xnovas versões minor e patch
~1.0.4 · 1.0 · 1.0.xsó patch
1.0.4exatamente essa

O uses mínimo

uses
  LzNex,                 // a facade: Connect, NewConfig, ILzNex, ILzNexQuery...
  LzNex.Client.MySQL;    // o dialeto. Sem esta linha, Connect levanta.

Troque a segunda linha pela unit do seu banco — ou ponha mais de uma, se o programa fala com mais de um:

UnitRegistra o client
LzNex.Client.MySQL'mysql', 'mariadb'
LzNex.Client.Postgres'postgresql', 'postgres'
LzNex.Client.Firebird'firebird' — serve ao Firebird 3 e ao 5
LzNex.Client.SQLite'sqlite', 'sqlite3'
⚠
Armadilha estrutural do Pascal

O linker do FPC descarta unit que ninguém referencia em uses. Unit descartada não executa seu initialization — e é ali que o dialeto se registra no registry. O sintoma é Dialect "x" is not registered. Available: … em tempo de execução, sem erro de compilação. A mesma regra vale para migrations e seeds escritas em Pascal.

Programa com threads

Em Unix, programa que usa threads precisa de cthreads no início do uses do .lpr — antes de qualquer outra unit: 

uses
  {$IFDEF UNIX}{$IFDEF UseCThreads}
  cthreads,
  {$ENDIF}{$ENDIF}
  SysUtils, Horse, LzNex, LzNex.Client.MySQL;
