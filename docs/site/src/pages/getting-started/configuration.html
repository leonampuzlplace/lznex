Configuração

Três caminhos de entrada, do mais explícito ao mais automático — e eles se compõem.

  1. NewConfig.Client('mysql').Host(…) — em código;
  2. LoadConfigFile('database/lznex.json', 'development') — arquivo, por ambiente;
  3. ApplyEnvOverrides(Cfg) — variáveis LZNEX_* do processo.

O caminho do arquivo já aplica as LZNEX_* por cima do que leu. É isso que faz a mesma imagem de container servir para dev, CI e produção.

Arquivo JSON

A chave default escolhe o ambiente quando ninguém informa; cada ambiente é um objeto no primeiro nível. Um arquivo que tenha client ou connection na raiz é tratado como configuração única, sem ambientes. 

{
  "default": "development",
  "development": {
    "client": "mysql",
    "connection": {
      "host": "mysql",
      "port": 3306,
      "database": "lznex",
      "user": "root",
      "password": "secret",
      "charset": "utf8mb4",
      "libraryLocation": "/usr/lib/x86_64-linux-gnu/libmariadb.so.3"
    },
    "pool": { "min": 2, "max": 10, "acquireTimeout": 30000 },
    "migrations": { "table": "migrations", "directory": "database/migrations" },
    "seeds": { "directory": "database/seeds" },
    "props": { "timezone": "UTC" }
  },
  "test": {
    "client": "mysql",
    "connection": { "host": "mysql", "database": "lznex_test", "user": "root", "password": "secret" },
    "pool": { "min": 1, "max": 4 }
  }
}

As chaves de conexão podem ficar dentro de connection ou soltas no nó do ambiente — o leitor procura primeiro no aninhado, depois na raiz do ambiente. Chave desconhecida em props é repassada ao driver sem a config ter que conhecê-la. 

// o ambiente vem do parametro, de LZNEX_ENV, da chave "default" ou 'development'
Db := ConnectFromFile('database/lznex.json', 'test');

// ou, separando leitura de conexao:
Cfg := LoadConfigFile('database/lznex.json', '');
Cfg.Pool(1, 4);
Db := Connect(Cfg);

Ambiente inexistente levanta ELzNexConfig listando as chaves de primeiro nível do arquivo.

Variáveis de ambiente

Reconhecidas por ApplyEnvOverrides (e já aplicadas por LoadConfigFile). Variável vazia ou ausente não mexe no que já estava: a sobrescrita é sempre aditiva. Valor numérico inválido levanta — erro de deploy não é algo para silenciar com default.

Para testar sobrescrita sem mexer no processo, use ApplyOverrides(Cfg, Vals(['host', 'db2', 'pool_min', '1'])) — a chave aceita tanto LZNEX_HOST como host.

A biblioteca cliente de cada banco

O auto-load do Zeos procura nomes que nem sempre existem na distribuição — no Ubuntu isso falha em todos os quatro. Informe o caminho por LibraryLocation ou LZNEX_LIBRARY. Os caminhos abaixo são os do Ubuntu 26.04, com o pacote que os traz:

DialetoLibraryLocationPacote
MySQL / MariaDB/usr/lib/x86_64-linux-gnu/libmariadb.so.3libmariadb3
PostgreSQL/usr/lib/x86_64-linux-gnu/libpq.so.5libpq5
Firebird/usr/lib/x86_64-linux-gnu/libfbclient.so.2libfbclient2
SQLite/usr/lib/x86_64-linux-gnu/libsqlite3.so.0libsqlite3-0

SQLite é banco em arquivo

Não há servidor: Database é o caminho do arquivo e Host não se aplica. A validação sabe disso e deixa o host vazio passar quando o client é sqlite ou sqlite3 — nos outros dialetos host vazio continua levantando. 

Db := Connect(NewConfig
  .Client('sqlite')
  .Database('/var/lib/app/app.sqlite')
  .LibraryLocation('/usr/lib/x86_64-linux-gnu/libsqlite3.so.0'));

No Firebird o Database também é um caminho de arquivo — mas no servidor, não no cliente, e o Host continua obrigatório. 

Db := Connect(NewConfig
  .Client('firebird').Host('firebird5').Port(3050)
  .Database('/var/lib/firebird/data/app.fdb')
  .User('SYSDBA').Password('secret')
  .LibraryLocation('/usr/lib/x86_64-linux-gnu/libfbclient.so.2'));

Charset e defaults por protocolo

O default de charset do pacote é utf8mb4, que é nome do MySQL e não existe nos outros bancos. Quando o charset não é escolhido à mão, a camada de conexão o traduz: UTF8 no Firebird, UTF-8 no SQLite. Charset informado explicitamente passa intacto.

Antes de abrir, o LzNex também aplica alguns defaults de driver por protocolo. Todos são sobrescrevíveis por Prop (ou por props no JSON):

ProtocoloPropriedades aplicadasPor quê
MySQL / MariaDB MySQL_FieldType_Bit_1_IsBoolean=True bit(1) volta como booleano, não como byte
Firebird hard_commit=True sem isso o Zeos faz commit retendo a transação, e a conexão do pool continuaria na mesma foto, sem ver o commit das outras
SQLite busytimeout=5000, journal_mode=wal, foreign_keys=on espera em vez de falhar quando o arquivo está trancado, deixa leitor e escritor conviverem, e liga a checagem de chave estrangeira — que no SQLite vem desligada

O Firebird ainda abre a conexão em read committed em vez do snapshot que é default do servidor, pela mesma razão do hard_commit. Veja Dialetos.

Validação

Connect chama Validate antes de abrir qualquer coisa. Levanta ELzNexConfig se faltar client, host (exceto em SQLite) ou database, se a porta não for positiva, se o máximo do pool for menor que 1, se o mínimo passar do máximo, ou se o timeout for negativo.
