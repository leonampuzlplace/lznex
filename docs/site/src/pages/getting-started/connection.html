Conexão

Connect valida a configuração, resolve o dialeto e abre o pool. O que ele devolve — ILzNex — é o ponto de entrada para tudo. 

var
  Db: ILzNex;
begin
  Db := Connect(NewConfig
    .Client('mysql')
    .Host('mysql')
    .Port(3306)
    .Database('app')
    .User('root')
    .Password('secret')
    .Charset('utf8mb4')
    .LibraryLocation('/usr/lib/x86_64-linux-gnu/libmariadb.so.3')
    .Pool(2, 10)
    .AcquireTimeout(30000));
  try
    // ... use Db ...
  finally
    Db.Shutdown;
  end;
end;

Uma instância por processo é o padrão: a facade é dona do pool, e é o pool que serializa o acesso concorrente. Não crie ILzNex por requisição HTTP.

⚠
LibraryLocation

O auto-load do Zeos não acerta o nome da biblioteca no Ubuntu, em nenhum dos quatro dialetos. Informar LibraryLocation (ou a variável LZNEX_LIBRARY) é, na prática, obrigatório. Sem isso o sintoma é um erro de biblioteca ao conectar. Os caminhos de cada um estão em Configuração.

Dialetos registrados

UnitClient(…)DialectName
LzNex.Client.MySQL'mysql', 'mariadb'mysql
LzNex.Client.Postgres'postgresql', 'postgres'postgresql
LzNex.Client.Firebird'firebird'firebird
LzNex.Client.SQLite'sqlite', 'sqlite3'sqlite

Nome não registrado levanta ELzNexConfig. Para checar antes: IsClientRegistered('mysql'), de LzNex.Client; RegisteredClients devolve a lista do que está disponível. Note que o DialectName é um só por dialeto, mesmo quando há dois nomes de registro: Client('sqlite3') devolve um cliente cujo DialectName é sqlite.

Ciclo de vida

  • Connect abre o pool já com o mínimo de conexões configurado;
  • cada query pega uma conexão emprestada e devolve sozinha ao terminar;
  • Shutdown fecha as conexões ociosas e marca o pool como encerrado;
  • depois do Shutdown, qualquer Acquire levanta ELzNexPool.
