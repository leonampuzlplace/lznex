Join e upsert

ILzNexJoin e ILzNexOnConflict: as duas interfaces que ILzNexQuery devolve quando a próxima chamada precisa ser restringida.

ILzNexJoin

Herda ILzNexQuery inteira: depois das cláusulas On* você continua a query na mesma expressão — Where, OrderBy, outro Join, o terminal. As cláusulas vão sempre para o join corrente, o último aberto por Join, LeftJoin, JoinSub e companhia; um On* sem join antes levanta ELzNexBuilder.

⚠
OnColumns compara identificador, OnValue gera bind

OnColumns('posts.user_id', '=', 'users.id') compara duas colunas e não produz nenhum bind; OnValue('tags.active', '=', True) produz on `tags`.`active` = ?. São dois métodos porque um só teria que adivinhar pelo tipo — e True viraria comparação com uma coluna chamada True, erro que não aparece nem na compilação nem no resultado.

Os And* existem só para deixar o encadeamento legível: o conector padrão já é and.

function OnColumns(const ALeft, AOp, ARight: string): ILzNexJoinColuna contra coluna. Os dois lados são identificadores.
function OnValue(const AColumn, AOp: string; const AValue: TLzNexValue): ILzNexJoinColuna contra valor. O valor entra como bind.
function AndOnColumns(const ALeft, AOp, ARight: string): ILzNexJoinIgual a OnColumns, com o and explícito na leitura.
function OrOnColumns(const ALeft, AOp, ARight: string): ILzNexJoinMesma comparação, conector or.
function AndOnValue(const AColumn, AOp: string; const AValue: TLzNexValue): ILzNexJoinIgual a OnValue.
function OrOnValue(const AColumn, AOp: string; const AValue: TLzNexValue): ILzNexJoinComparação com valor, conector or.
function OnIn(const AColumn: string; const AValues: TLzNexValues): ILzNexJoinon ... in (?, ?), um bind por valor.
function OnNull(const AColumn: string): ILzNexJoinon ... is null.
function OnNotNull(const AColumn: string): ILzNexJoinon ... is not null.
function OnBetween(const AColumn: string; const ALo, AHi: TLzNexValue): ILzNexJoinon ... between ? and ?.
function OnRaw(const ASQL: string; const AArgs: array of const): ILzNexJoinPredicado cru dentro do ON, com a gramática de SQL cru.
function Using(const AColumns: array of string): ILzNexJoinusing (`a`, `b`) em vez de ON. Lista vazia levanta ELzNexBuilder.

Clone não herda o join corrente: num clone, as cláusulas On* precisam de um Join novo. Exemplos com o SQL de cada cláusula em Joins.

ILzNexOnConflict

OnConflict não devolve ILzNexQuery de propósito: o tipo de retorno só tem estes quatro métodos, então esquecer de completar a cláusula é erro de compilação, não um insert silenciosamente sem o on conflict. Cada um devolve a query de volta, e aí vem o Insert.

function Ignore: ILzNexQueryDescarta a linha conflitante: insert ignore no MySQL, on conflict do nothing no Postgres.
function Merge: ILzNexQueryAtualiza todas as colunas do insert com o valor que veio nele.
function Merge(const AColumns: array of string): ILzNexQueryAtualiza só as colunas listadas, com o valor do insert.
function MergeValues(const AValues: TLzNexNamedValues): ILzNexQueryAtualiza com valores próprios, independentes do insert. Lista vazia levanta ELzNexBuilder.
ℹ
Unset em MergeValues reaproveita o valor do insert

Em MergeValues, uma coluna cujo valor é TLzNexValue.Unset não gera bind: ela sai como excluded.coluna (ou values(coluna) no MySQL), isto é, com o valor que veio no Insert. É assim que se mistura, numa chamada só, coluna com valor fixo e coluna copiada do insert.

No Postgres e no SQLite, Merge exige as colunas de conflito — OnConflict([]) seguido de Merge levanta ELzNexCompile, porque do update sem alvo não é SQL válido. Ignore aceita a lista vazia. No Firebird é o oposto: update or insert sem matching casa pela chave primária, e é Ignore que não tem equivalente. O SQL de cada combinação em cada banco está em Upsert.
