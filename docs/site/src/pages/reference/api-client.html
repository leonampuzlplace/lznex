Dialeto e compiladores

O que um dialeto precisa responder e as duas interfaces que transformam árvore em texto.

ILzNexClient

O dialeto. Nenhum método aqui toca no banco: é tudo pergunta sobre como escrever SQL. O builder e os compiladores consultam esta interface e nunca testam o nome do banco com if — acrescentar um dialeto é implementar isto, não editar o compilador.

Léxico

Como identificador, apelido, placeholder e valor de log são escritos.

function DialectName: stringNome do dialeto em minúsculas ('mysql', 'postgresql', 'firebird', 'sqlite'). É a chave do registro e o que LastInsertId consulta para escolher a consulta certa. Um dialeto pode estar registrado sob mais de um nome e ainda assim ter um só DialectName: 'sqlite3' devolve 'sqlite'.
function ZeosProtocol: stringProtocolo da URL do Zeos. Separado do nome porque os dois não precisam coincidir.
function WrapIdentifier(const AName: string): stringEnvolve um nome simples. O caractere de quote dentro do nome é dobrado, o que fecha a porta para injeção via identificador; * e vazio passam intactos.
function WrapQualified(const AName: string): stringEnvolve um nome com pontos, parte por parte, e entende ' as ' no meio — 'a.id as x' sai com os três pedaços tratados.
function Alias(const AExpr, AAlias: string): stringCola expressão e apelido. Apelido vazio devolve só a expressão.
function Placeholder(const AIndex: Integer): stringMarcador de bind. Devolve ? em todos os dialetos; o índice existe para um dialeto que numere os binds.
function EscapeForLog(const AValue: TLzNexValue): stringValor interpolado. Dois usos: o que o log mostra no lugar de cada bind, e o literal de DEFAULT no DDL. Não serve para montar o corpo de uma query — binário vira <n bytes> e valor não setado vira <unset>. Booleano é o ponto de divergência: true/false em PostgreSQL e Firebird, porque 1/0 é recusado numa coluna boolean.

Capacidades

Seis perguntas booleanas, mais uma que não é. O compilador usa as respostas para emitir a forma nativa ou cair num equivalente, o migrator usa DdlIsTransactional para avisar sobre DDL, e a camada de conexão usa DefaultIsolation ao abrir. Os valores de cada dialeto estão em dialetos.

function SupportsReturning: BooleanSe returning existe. Onde não existe, Returning no builder levanta ELzNexCompile em vez de sair do SQL em silêncio.
function SupportsOnConflictWhere: BooleanSe o tratamento de conflito aceita predicado próprio.
function SupportsNullsOrdering: BooleanSe nulls first / nulls last existe no order by.
function SupportsDistinctOn: BooleanSe distinct on existe.
function SupportsSavepoints: BooleanSe savepoint é suportado. True na base.
function SupportsJson: BooleanSe há tipo e funções de JSON. False na base e no Firebird; True em MySQL, PostgreSQL e SQLite — é o que faz WhereJson* recusar antes de gerar SQL.
function SupportsFullText: BooleanSe há índice e busca de texto completo em tabela comum. True só em MySQL e PostgreSQL.
function IsRetryableError(const ACode: Integer; const ASQLState: string): BooleanSe vale repetir a transação depois deste erro. A base aceita os SQLSTATE 40001 e 40P01; cada dialeto acrescenta seus códigos nativos. É o que Transact consulta.
function DdlIsTransactional: BooleanFalse quando DDL dá commit implícito. É o que faz o migrator emitir o aviso de que um rollback não vai desfazer o create/alter/drop já executado.
function DefaultIsolation: TLzNexIsolationNível em que a conexão nasce. ilDefault na base — não mexe no default do servidor. Só o Firebird sobrescreve, para ilReadCommitted: o default dele é snapshot, e snapshot num pool deixa a conexão sem ver o commit das outras.

Estrutura da compilação

Em vez de cada verbo ter sua rotina de montagem, o compilador percorre a lista de componentes que o dialeto declara para aquele verbo. Mudar a ordem do limit ou excluir um componente é mexer nestes dois métodos, não no compilador.

function Components(const AMethod: TLzNexQueryMethod): TLzNexComponentsComponentes que o verbo emite, na ordem do texto final. Um select vai de cpHints a cpLock; um insert só tem cpFrom.
function InvalidComponents(const AMethod: TLzNexQueryMethod): TLzNexComponentsComponentes que, se estiverem preenchidos no builder, são erro para aquele verbo. É o que faz um having pendurado num delete levantar ELzNexCompile antes de virar SQL, em vez de ser silenciosamente ignorado.

Fábricas

function NewCompiler: ILzNexCompilerCompilador de query do dialeto, já amarrado a este client.
function NewSchemaCompiler: ILzNexSchemaCompilerCompilador de DDL. Devolver nil aqui faz o schema levantar ELzNexSchema com o nome do dialeto.

ILzNexCompiler

O compilador recebe a AST, não o builder: Compile toma um TLzNexAst e devolve um TLzNexFragment — texto mais binds na ordem do texto. A separação é deliberada e vale pelo que permite nos testes: dá para montar uma AST à mão e compilar sem builder, e dá para exercitar o builder olhando só a AST, sem compilar. Nenhum dos dois lados precisa de banco.

function Compile(const AAst: TLzNexAst): TLzNexFragmentCompila a query inteira. Valida os componentes contra o verbo antes de emitir; AST nil ou verbo não suportado levantam ELzNexCompile.
function CompilePredicates(const AGroup: TLzNexStatementGroup; const AItems: TLzNexStatementList): TLzNexFragmentCompila uma lista de predicados sem o where/having em volta, intercalando and/or conforme o conector de cada statement. É o que permite reusar a mesma rotina em where, having, on de join e grupo aninhado. Lista vazia devolve fragmento vazio.
function Client: ILzNexClientDialeto deste compilador.

ILzNexSchemaCompiler

O equivalente para DDL. Lê o builder pela parte de leitura de ILzNexTable e devolve fragmentos — inclusive para as operações que não passam por builder nenhum, como drop e truncate.

function CompileTable(const ATable: ILzNexTable): TLzNexDdlPlanCompila o builder inteiro. Decide entre create e alter pelo TableMethod; nil levanta.
function ColumnTypeSQL(const AType: TLzNexColumnType; const AParam1, AParam2: Integer; const AItems: TLzNexValues): stringTipo lógico → tipo do banco. Recebe os dois parâmetros do tipo e os itens do enum porque é o único ponto que precisa deles.
function ModifierOrder: TLzNexColumnModifiersOrdem em que os modificadores saem na definição da coluna. Cada dialeto tem a sua, e modificador fora da lista simplesmente não é emitido.
function DropTableSQL(const ATable: string; const AIfExists: Boolean): TLzNexFragmentdrop table, com ou sem if exists.
function RenameTableSQL(const AFrom, ATo: string): TLzNexFragmentRenomeia tabela.
function TruncateTableSQL(const ATable: string): TLzNexFragmenttruncate table.
function HasTableSQL(const ATable, ASchema: string): TLzNexFragmentConsulta de existência da tabela. Nome e schema vão como bind, não interpolados; schema vazio é omitido do predicado.
function HasColumnSQL(const ATable, AColumn, ASchema: string): TLzNexFragmentO mesmo para coluna.
function TablesSQL(const ASchema: string): TLzNexFragmentLista de tabelas: uma coluna de texto por linha. Base em information_schema; cada dialeto sobrescreve com o seu catálogo.
function ColumnsSQL(const ATable, ASchema: string): TLzNexFragmentColunas na ordem de declaração, uma coluna de texto por linha.
function HasIndexSQL(const ATable: string; const AColumns: TLzNexValues; const ASchema: string): TLzNexFragmentUma linha com um contador: maior que zero significa que existe índice cobrindo exatamente aquelas colunas.
function IndexName(const ATable: string; const AColumns: TLzNexValues; const AKind: TLzNexIndexKind): stringNome derivado do índice: tabela, colunas e o sufixo do tipo, tudo em minúsculas e com . e - trocados por _. Um ConstraintName no builder tem precedência sobre isto.

ILzNexRaw

SQL cru já com os argumentos capturados. O texto só é resolvido quando um dialeto aparece — identificador precisa do quote certo, e isso o builder não sabe na hora da chamada. Veja SQL cru para a gramática dos marcadores.

function Build(const AClient: ILzNexClient): TLzNexFragmentResolve o template contra o dialeto: devolve o texto com os placeholders no lugar e os binds na ordem em que aparecem.
function Template: stringO texto como foi escrito, com os marcadores ainda crus. Útil em mensagem de erro e em teste.

TLzNexDdlPlan

Um DDL raramente é um comando só: índice, comentário e renomeação podem precisar de statements próprios, e alguns precisam vir antes ou depois do principal. O plano guarda os três grupos em ordem.

Pre: TLzNexFragmentsO que roda antes do comando principal.
Statements: TLzNexFragmentsO comando principal — o create table ou os alter table.
Post: TLzNexFragmentsO que roda depois: índices, comentários e o que o dialeto não consegue colocar inline.
function All: TLzNexFragmentsOs três concatenados em ordem de execução. É exatamente o que Execute percorre.
function Count: IntegerTotal de comandos no plano, sem montar o array de All.
