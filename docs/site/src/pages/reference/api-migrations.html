Migrations e seeds

As interfaces do migrator e as duas classes base que você herda para escrever uma migration ou um seed em código.

ILzNexMigration

Uma migration é identificada por dois textos: o Name completo, que é o que fica gravado na tabela de controle, e o Id, que define a ordem de aplicação. Id duplicado é erro de registro, não de execução.

function Id: stringChave de ordenação. Comparada como texto, então o formato de data fixa a ordem.
function Name: stringNome completo. É por ele que o migrator decide se já foi aplicada.
function UseTransaction: BooleanFalse faz o migrator rodar Up/Down sem transação, direto na fachada. Serve para DDL que o banco recusa dentro de transação.
procedure Up(const ADb: ILzNex)Aplica. O ADb recebido é a transação quando UseTransaction é verdadeiro — use só ele, não a fachada global.
procedure Down(const ADb: ILzNex)Desfaz, com a mesma regra.

TLzNexMigration

Classe base de LzNex.Migration, para migrations escritas em Pascal. Ela implementa ILzNexMigration redirecionando Id e Name para os métodos de classe — assim o registro consegue ler o id sem instanciar a migration.

class function Id: string; virtualPor padrão, o pedaço de MigrationName antes do primeiro _. Sobrescreva só se o nome não seguir o formato.
class function MigrationName: string; virtualObrigatório sobrescrever: a versão da base levanta ELzNexMigration dizendo para devolver '<YYYYMMDDHHMMSS>_<description>'.
function UseTransaction: Boolean; virtualTrue na base. Sobrescreva para sair da transação.
procedure Up(const ADb: ILzNex); virtual; abstractObrigatório: é abstrato.
procedure Down(const ADb: ILzNex); virtual; abstractObrigatório: é abstrato. Migration irreversível deve levantar aqui, não ficar vazia.

Uma subclasse só entra na fila depois de RegisterMigration(TMinhaMigration), que insere já ordenado por Id e recusa id repetido. O registro acontece no initialization da unit da migration — e é aí que mora a armadilha do linker: migrations explica por que a unit precisa aparecer num uses agregador.

ILzNexMigrationSource

Fonte de migrations. O migrator aceita várias e mistura tudo numa fila só, ordenada por Id; id repetido entre fontes levanta apontando as duas.

function All: TLzNexMigrationArrayTodas as migrations da fonte, instanciadas.
function SourceName: stringRótulo que aparece no Status e nas mensagens de erro.

Duas implementações vêm prontas: TLzNexCodeMigrationSource (nome 'code'), que devolve as classes registradas, e TLzNexSqlMigrationSource (nome 'sql'), que lê pares .up.sql / .down.sql de um diretório. A variante NewOptional aceita diretório inexistente sem reclamar.

ILzNexMigrator

Obtido em Db.Migrator, já com a fonte de código e — se a config apontar um diretório — a fonte de arquivos. Os métodos que mudam o banco pegam um lock na tabela <migrations>_lock e o soltam no fim, inclusive quando a migration falha.

function AddSource(const ASource: ILzNexMigrationSource): ILzNexMigratorAcrescenta uma fonte e devolve o próprio migrator. nil levanta.
function Latest: IntegerAplica todas as pendentes num mesmo lote e devolve quantas rodaram.
function Rollback: IntegerDesfaz o último lote inteiro, na ordem inversa da aplicação.
function RollbackAll: IntegerDesfaz tudo que está aplicado, do fim para o começo.
function Up(const AName: string = ''): IntegerSem nome, aplica apenas a próxima pendente. Com nome, aplica aquela — já aplicada ou inexistente levanta.
function Down(const AName: string = ''): IntegerSem nome, desfaz a última aplicada. Com nome, desfaz aquela — não aplicada levanta.
function MigrateTo(const AName: string): IntegerAplica as pendentes até a migration indicada, inclusive, e para ali.
function Status: TLzNexMigrationStatusListUma linha por migration conhecida, aplicada ou não. Não pega o lock.
function Pending: TLzNexMigrationArraySó as que faltam, em ordem de aplicação. Não pega o lock.
function CurrentVersion: stringMaior Id aplicado, ou 'none' quando a tabela está vazia.
procedure UnlockSolta o lock à mão, para o caso de um processo ter morrido segurando ele.
procedure EnsureTablesCria a tabela de controle e a de lock se faltarem. Os outros métodos chamam isto antes; a checagem é feita uma vez por migrator.
⚠
Migration aplicada que desapareceu da fonte trava tudo

Antes de qualquer operação o migrator compara a tabela de controle com as fontes, por nome. Linha gravada sem migration correspondente levanta ELzNexMigration listando as órfãs — o que acontece ao renomear ou apagar um arquivo já aplicado, ou ao tirar a unit do agregador e deixá-la de fora do link. Restaure a migration ou apague a linha à mão.

ILzNexSeeder

Seeds não têm tabela de controle nem lote: rodam sempre que você pede. A ordem é a alfabética do SeedName, comparada sem caixa.

function Run: IntegerRoda todos os seeds registrados, em ordem de nome, e devolve a quantidade.
function RunOne(const AName: string): IntegerRoda um seed pelo nome. Nome desconhecido levanta listando os registrados — e, quando não há nenhum, lembra que a unit pode não estar no uses agregador.
function Names: TLzNexStringArrayNomes registrados, na ordem de execução.

TLzNexSeed

A classe base do seed é um TObject comum, não uma interface: o seeder instancia, executa e libera. Falha dentro do Run é reembalada com o nome do seed e da classe.

class function SeedName: string; virtualObrigatório sobrescrever: a base levanta. O nome define a ordem e é a chave do RunOne.
procedure Run(const ADb: ILzNex); virtual; abstractObrigatório. Recebe a fachada; se quiser atomicidade, abra a transação aqui dentro.

Registre com RegisterSeed(TMeuSeed), que recusa nome vazio ou repetido. Veja seeds.

TLzNexMigrationStatus

O record devolvido por Status, um por migration conhecida. Para as não aplicadas, os três últimos campos vêm zerados.

Name: stringNome completo da migration.
Source: stringSourceName da fonte de onde ela veio — 'code' ou 'sql'.
Applied: BooleanSe há linha correspondente na tabela de controle.
Batch: IntegerLote em que foi aplicada; 0 se não foi. É o lote que o Rollback desfaz.
AppliedAt: TDateTimeMomento da aplicação; 0 se não foi.
