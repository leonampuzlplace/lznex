Conexão, pool e transação

As três interfaces que ficam entre o builder e o Zeos: quem executa, quem empresta e quem delimita.

ILzNexConnection

A camada fina sobre o Zeos. Recebe TLzNexFragment — texto mais binds já prontos — e nunca interpola valor. Statements preparados ficam num cache por conexão, e um prepare ou execução que falha remove a entrada do cache antes de propagar o erro.

function Execute(const AFragment: TLzNexFragment): Int64Roda um comando que não devolve linhas e entrega as linhas afetadas. Fragmento com texto vazio levanta ELzNexQuery.
function Query(const AFragment: TLzNexFragment): ILzNexResultRoda um comando que devolve cursor. Comando que não produz resultset levanta.
function ExecuteScript(const ASQL: string): Int64Executa SQL sem bind nem prepare, por statement direto. É o caminho de migration em arquivo e de DDL que o driver recusa preparado.
function LastInsertId: Int64Último id gerado nesta conexão.
function StartTransaction: IntegerAbre transação ou savepoint e devolve o nível resultante.
procedure CommitConfirma o nível atual e decrementa o contador.
procedure RollbackDesfaz o nível atual e decrementa o contador.
function InTransaction: BooleanPergunta ao driver: conexão aberta e sem autocommit. Não depende do contador interno.
function TransactionLevel: IntegerNível conhecido pela conexão. É o que detecta savepoint aberto quando a transação externa vai fechar.
function Ping: BooleanTesta o servidor. Nunca levanta: qualquer falha vira False. O pool usa isso para descartar conexão morta.
function IsClosed: BooleanVerdadeiro se já foi fechada ou nunca abriu.
procedure CloseLimpa o cache de statements e fecha. Idempotente e não levanta.
function Native: IInterfaceEscapatória: o IZConnection do Zeos por baixo.
function Client: ILzNexClientDialeto desta conexão.
ℹ
Native é a porta de saída para uso avançado

O tipo declarado é IInterface para não espalhar ZDbcIntfs pela API pública; faça Conn.Native as IZConnection quando precisar de algo que o LzNex não expõe (isolamento sob medida, metadados do driver). Depois de Close devolve nil.

⚠
LastInsertId é por conexão

Ele roda uma consulta — select last_insert_id(), select lastval() ou select last_insert_rowid(), conforme o DialectName — e o valor só existe na sessão que fez o insert. Lido de outra conexão do pool o resultado não é seu: pegue o id na mesma conexão, ou use InsertGetId, que já cuida disso.

ILzNexPool

Pool fixo com mínimo e máximo. As conexões do mínimo abrem na construção; o resto abre sob demanda até o máximo. Acquire devolve uma conexão emprestada — um invólucro que delega tudo para a conexão real.

function Acquire: ILzNexConnectionPega uma conexão livre, testando com Ping e descartando as mortas; se não houver livre e o máximo não foi atingido, abre uma. Bloqueia até o timeout de aquisição da config e então levanta ELzNexPool.
function Size: IntegerTotal de conexões vivas: as livres mais as em uso.
function InUse: IntegerQuantas estão emprestadas agora.
procedure ShutdownMarca o pool como encerrado e fecha as livres. Acquire depois disso levanta; as emprestadas continuam funcionando e são fechadas, não guardadas, ao voltar.
⚠
A devolução é automática — e é por isso que o pool pode travar

Não existe Release na interface: a conexão volta ao pool no destrutor do invólucro, quando o refcount do ILzNexConnection chega a zero. Na volta, uma transação ainda aberta sofre rollback e uma conexão fechada é descartada em vez de guardada. O efeito prático: guardar a interface num campo de objeto, num singleton ou numa closure mantém a conexão emprestada para sempre e esgota o pool — o erro de exaustão diz exatamente isso. Deixe a variável sair de escopo.

Um ILzNexResult obtido de conexão emprestada também segura o empréstimo: o cursor guarda uma referência à conexão, então o pool só a recupera quando o resultado é liberado. Veja pool para os números medidos e resultados para o ciclo do cursor.

ILzNexTransaction

ILzNexTransaction herda de ILzNex: dentro de uma transação você usa a mesma fachada de sempre — Table, From, Query, Schema, Execute, Fetch — e as queries saem já amarradas nela, sem precisar de Transacting à mão. Os cinco métodos próprios são os de controle.

procedure CommitConfirma e encerra. Com savepoint interno ainda aberto, levanta ELzNexTransaction em vez de confirmar pela metade.
procedure RollbackDesfaz e encerra, com a mesma checagem de savepoint aberto.
function Savepoint: ILzNexTransactionBloco interno sobre a mesma conexão. Savepoints fecham em ordem LIFO.
function IsCompleted: BooleanVerdadeiro depois de Commit ou Rollback. É o que permite um except fazer rollback só quando ainda há o que desfazer.
function Level: IntegerNível desta transação na conexão, como o driver reportou ao abrir. Cada savepoint sobe um.
⚠
Commit e Rollback soltam a conexão na hora

Os dois zeram a referência interna no mesmo instante, o que devolve o empréstimo ao pool. Depois disso a transação está encerrada: Connection levanta com essa explicação, e Table, Execute ou qualquer outro método de trabalho levantam dizendo em que nível a transação estava. Para continuar, abra outra transação.

Se a transação é liberada sem Commit nem Rollback, o destrutor faz rollback — e, se esse rollback falhar, registra no logger em vez de levantar de dentro do destrutor. Shutdown numa transação levanta de propósito: encerre o bloco e chame Shutdown na fachada. Veja transações para os exemplos.
