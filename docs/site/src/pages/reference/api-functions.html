Funções de módulo

Toda função e procedimento público do LzNex, com a unit de origem. São as portas de entrada: interface só se obtém por uma destas.

Índice completo

A biblioteca não exporta construtor de classe — tudo que devolve interface é uma função New* ou Create* na unit correspondente. A coluna da direita é o que você precisa pôr no uses.

Fachada e configuração

Connect valida a configuração, resolve o dialeto por nome e abre o pool — AConfig = nil levanta ELzNexConfig. ConnectFromFile é só Connect(LoadConfigFile(APath, AEnv)), e é o caminho que o CLI usa. NewConfig e TLzNexConfig.New devolvem a mesma coisa; a primeira existe para quem tem apenas LzNex no uses. TLzNexConsoleLogger.New é o logger de console pronto; com ALogQueries = False ele emite só erro, aviso e info.

ApplyOverrides recebe pares nome/valor e aplica os que reconhece (CLIENT, HOST, PORT, DATABASE, USER, PASSWORD, CHARSET, LIBRARY, POOL_MIN, POOL_MAX, ACQUIRE_TIMEOUT, MIGRATIONS_TABLE, MIGRATIONS_DIR, SEEDS_DIR); qualquer outra chave vira uma prop de conexão em caixa baixa. Valor vazio é ignorado, e não sobrescreve o que já estava lá. EnvOverrideNames devolve as 14 variáveis de ambiente equivalentes, todas com o prefixo LZNEX_, e é o que ApplyEnvOverrides percorre.

LoadConfigJSON já chama ApplyEnvOverrides no fim, e LoadConfigFile delega a ele — então arquivo carregado já veio com as variáveis de ambiente aplicadas. Chamar ApplyEnvOverrides à mão só é necessário sobre uma configuração montada em código.

Registro de dialeto

CreateClient procura o nome num dicionário em caixa baixa e com Trim, e levanta ELzNexConfig listando os nomes disponíveis quando não acha. Os nomes são registrados no initialization da unit do dialeto: LzNex.Client.MySQL registra mysql e mariadb, LzNex.Client.Postgres registra postgresql e postgres.

⚠
O linker do FPC descarta a unit não referenciada

Se a unit do dialeto não aparece no uses de ninguém, o initialization dela nunca roda e CreateClient('mysql') falha com "dialect is not registered" — mesmo que o arquivo esteja no projeto. Inclua LzNex.Client.MySQL (ou .Postgres) explicitamente no programa principal. RegisteredClients devolve <none> quando nenhuma foi linkada, o que é o sintoma mais direto.

Auxiliares de texto

NormalizeOperator baixa a caixa, apara e colapsa espaços repetidos antes de conferir contra LZNEX_OPERATORS; fora da lista, levanta ELzNexBuilder. SplitQualified quebra 'db.schema.col' pelos pontos e apara cada parte. FindAliasSeparator devolve a posição (base 1) do ' as ' — em qualquer caixa — ou 0 se não houver, e é como 'users as u' numa string só é reconhecido.

MigrationIdOf extrai o id de um nome de migração: tudo antes do primeiro _. Sem _, ou com _ na primeira posição, o nome inteiro é o id. MigrationTimestamp produz yyyymmddhhnnss em UTC — não em hora local, para que máquinas em fusos diferentes gerem ids ordenáveis entre si. Slugify baixa a caixa, troca todo caractere fora de a-z0-9 por _ sem repetir underscore, apara os do fim, e devolve 'migration' se nada sobrou. 

Slugify('Create Users Table!');      // create_users_table
Slugify('  ---  ');                  // migration
MigrationFileName('add index', False);  // M20260224183000_add_index.pas
MigrationFileName('add index', True);   // 20260224183000_add_index.up.sql

O nome Pascal é 'M' + timestamp + '_' + slug + '.pas'; o SQL é timestamp + '_' + slug + '.up.sql', e o par .down.sql é criado junto pelo CLI.

Registros globais

Migrações e seeds se registram em variáveis globais pelo initialization da própria unit, o mesmo mecanismo dos dialetos — e com a mesma armadilha de linker. RegisteredMigrationCount/At dão acesso indexado, RegisteredMigrations devolve o array inteiro, e FindMigrationClass casa por MigrationName exato (devolve nil se não achar, não levanta).

ClearMigrations e ClearSeeds existem para teste: zeram o registro global entre casos, para que um não veja o que o outro registrou. Em produção não há motivo para chamá-las.

Resultado e JSON

NewResult embrulha um IZResultSet do Zeos; o parâmetro AOwner é guardado só para manter vivo quem precisa continuar vivo (statement, conexão) enquanto o cursor estiver aberto — é o que evita o resultado sobreviver à conexão que o produziu. LzNexKindOfSQLType mapeia o tipo SQL do Zeos para o TLzNexValueKind correspondente, e é o que o leitor de coluna consulta uma vez por consulta, não por linha.

Os três LzNexJSON* são a serialização usada por ILzNexResult.ToJSON e ILzNexRow.ToJSON: LzNexJSONQuote escapa uma string, LzNexJSONValue converte um valor e LzNexJSONObject monta o objeto a partir de nomes e valores paralelos. No LzNexJSONValue: vkNull e vkUnset viram null, booleano vira true/false, número sai sem quotes, vkBytes sai em base64, data e hora saem como string (yyyy-mm-dd, hh:nn:ss, e datetime em yyyy-mm-ddThh:nn:ss).

Montar SQL sem banco nenhum

NewQuery precisa de um ILzNexClient, e NewSchema aceita nil no lugar do ILzNex. Com isso dá para gerar e inspecionar SQL sem abrir conexão, sem pool e sem servidor rodando — é exatamente assim que as suítes do projeto comparam o SQL por texto exato. 

uses
  LzNex.Types, LzNex.Value, LzNex.Fragment, LzNex.Intf,
  LzNex.Client, LzNex.Query, LzNex.Schema,
  LzNex.Client.MySQL;          // sem esta linha, CreateClient('mysql') falha

var
  Cli: ILzNexClient;
  F: TLzNexFragment;
  T: ILzNexTable;
begin
  Cli := CreateClient('mysql');

  F := NewQuery(Cli)
         .Table('users')
         .Where('id', 1)
         .ToSQL;

  Writeln(F.Text);                     // select * from `users` where `id` = ?
  Writeln(F.Bindings.Count);           // 1
  Writeln(F.Bindings.Describe);        // [integer(1)]

  T := NewSchema(nil, Cli).CreateTable('users');
  T.Increments;
  T.Str('email', 191).NotNull;

  Writeln(T.ToSQL.Statements[0].Text);
  // create table `users` (`id` int unsigned not null auto_increment primary key, `email` varchar(191) not null)
end.

Trocar 'mysql' por 'postgresql' (e incluir LzNex.Client.Postgres) muda o SQL dos dois sem mudar o código do builder: 

select * from `users` where `id` = ?
create table `users` (`id` int unsigned not null auto_increment primary key, `email` varchar(191) not null)
select * from "users" where "id" = ?
create table "users" ("id" serial primary key, "email" varchar(191) not null)
ℹ
Montar sim, executar não

Com NewSchema(nil, Cli), ILzNexTable.ToSQL funciona mas Execute não tem onde rodar. Mesma coisa para a query: ToSQL é puro, enquanto Get, First e Insert precisam de um ILzNex de verdade — use NewBoundQuery ou Db.Table(...) quando a intenção for executar.
