ILzNex

A facade devolvida por Connect: ponto de entrada para query, schema, migrations, transação e pool.

uses LzNex é o único uses obrigatório — a unit reexporta ILzNex, ILzNexQuery, TLzNexValue e os demais tipos do dia a dia, além de Connect, NewConfig e ConnectFromFile (veja Funções). A única unit extra que o programa precisa citar é a do dialeto, para o linker do FPC não descartar o registro — detalhe em Instalação.

ℹ
Ciclo de vida: ninguém escreve try/finally Free

Toda a API é COM com contagem de referência: o objeto morre quando a última referência sai de escopo. Para o contador poder chegar a zero, a referência existe só em um sentido — o filho guarda o pai (a query, o schema e o migrator guardam a facade), e o pai não guarda nenhum filho. Onde o filho precisa chamar o pai para fazer faxina, a referência é de classe, não de interface contada: é assim que a conexão emprestada chama o pool de volta para se devolver, sem que o ciclo se feche.

É por isso que Schema, Migrator e Seeder criam uma instância nova a cada acesso em vez de cachear: guardar a instância no campo da facade fecharia o ciclo facade → filho → facade, e nenhum dos dois seria liberado. Criar é barato (nenhum deles abre conexão no construtor), e o único recurso de verdade — o pool — é da facade e vive enquanto ela vive.

Montar queries

Os três primeiros devolvem uma query amarrada à facade: podem executar. Query é a forma de começar sem tabela, usada para subqueries.

function Table(const AName: string): ILzNexQueryNova query com a tabela já definida.
function From(const AName: string): ILzNexQueryIdêntico a Table.
function Query: ILzNexQueryQuery vazia, sem tabela. Para subquery e para montar a fonte depois.
function Raw(const ASQL: string; const AArgs: array of const): ILzNexRawTemplate de SQL cru com ?, ?? e :nome. Veja SQL cru.

Schema, migrations e seeds

Cada chamada devolve uma instância nova, pelo motivo do callout acima.

function Schema: ILzNexSchemaO schema builder: criar, alterar e inspecionar tabelas.
function Migrator: ILzNexMigratorO runner de migrations. Lê o nome da tabela de controle da configuração e nasce sem fonte: registre com AddSource.
function Seeder: ILzNexSeederO executor de seeds.

Transação

ILzNexTransaction herda ILzNex: dentro do bloco você usa Trx.Table(...) exatamente como usaria Db.Table(...), e a query já nasce amarrada à conexão da transação. O que a transação acrescenta é Commit, Rollback, Savepoint, IsCompleted e Level — detalhado em Transações.

Diferente de Schema e Migrator, abrir uma transação pega uma conexão do pool na hora e a segura até o Commit ou Rollback: transação esquecida viva é vaga do pool parada.

function Transaction: ILzNexTransactionAbre transação no nível de isolamento do servidor (ilDefault).
function Transaction(const AIsolation: TLzNexIsolation): ILzNexTransactionAbre com isolamento explícito: ilReadUncommitted, ilReadCommitted, ilRepeatableRead, ilSerializable.
function Transact(const AWork: ILzNexWork; const AAttempts: Integer = 1): IntegerAbre, roda o bloco, commita; em erro transitório desfaz e repete até AAttempts. Devolve quantas tentativas gastou. Chamado dentro de uma transação, levanta. Veja Transact.

ILzNexWork é a unidade de trabalho que Transact executa — uma interface com procedure Execute(const ADb: ILzNex). É interface e não callback pelo mesmo motivo de ILzNexMigration: sem função anônima no FPC 3.2, e o retry precisa rodar o mesmo bloco mais de uma vez.

SQL direto

Atalhos para quando não há o que construir: o texto vai como está, com os valores ainda como bind. Os dois pegam uma conexão emprestada do pool.

function Execute(const ASQL: string; const AArgs: array of const): Int64Executa e devolve linhas afetadas.
function Fetch(const ASQL: string; const AArgs: array of const): ILzNexResultExecuta e devolve o cursor.

Dialeto, configuração e conexão

Acesso ao que está por baixo. Client e Config devolvem a mesma instância a cada chamada — são do próprio objeto, criadas em Connect.

function Client: ILzNexClientO dialeto ativo: nome, quoting, capacidades. Veja ILzNexClient.
function Config: ILzNexConfigA configuração já validada por Connect.
function Pool: ILzNexPoolO pool, para ler Size / InUse em diagnóstico.
function Connection: ILzNexConnectionPega uma conexão emprestada do pool. Ela volta sozinha quando a referência sai de escopo.
function ReadConnection: ILzNexConnectionConexão do pool da réplica de leitura. Sem réplica configurada, é o mesmo que Connection; em ILzNexTransaction, é sempre a conexão da transação.
function IsTransaction: BooleanFalse na facade, True em ILzNexTransaction. Para código que recebe ILzNex e precisa saber onde está.
procedure ShutdownFecha as conexões ociosas e encerra o pool. Acquire depois disso levanta ELzNexPool.
⚠
Segurar a conexão prende uma vaga do pool

O empréstimo dura enquanto a ILzNexConnection (ou um ILzNexResult aberto a partir dela) estiver vivo. Guardar uma dessas em campo de objeto de vida longa é, na prática, tirar uma conexão do pool para sempre. Veja Pool.
