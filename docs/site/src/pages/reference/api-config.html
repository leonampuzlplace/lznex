Config e logger

ILzNexConfig é um par de setter encadeável e getter para cada campo, mais os defaults aplicados na construção.

ILzNexConfig

Todo setter devolve ILzNexConfig, então a configuração se escreve em cadeia. Os getters têm prefixo Get para não colidir com o setter de mesmo nome — é por isso que existe Client e GetClient em vez de uma propriedade. Nada aqui abre conexão: é só um saco de valores validado.

Notas que não cabem na tabela:

  • Client guarda o nome do dialeto ('mysql', 'postgresql') e é o que resolve o ILzNexClient no registro de dialetos — veja dialetos.
  • Pool valida na hora: mínimo negativo, máximo menor que 1 ou mínimo maior que o máximo levantam ELzNexConfig. É o único setter que critica o valor.
  • LibraryLocation aponta o arquivo da biblioteca cliente. Vale preencher quando o auto-load do Zeos não acha o .so/.dll — veja instalação.
  • Prop sobrescreve a chave existente comparando sem caixa, e as props vão para a URL de conexão do Zeos como propriedades extras. GetProps devolve uma cópia: alterar o array recebido não mexe na config.
  • Logger sem valor deixa a config sem logger, e aí nada é registrado — não há logger padrão implícito. Veja log.
procedure ValidateExige client, host e database preenchidos e critica porta, pool e timeout. A mensagem lista o que falta e as três formas de fornecer: código, arquivo JSON ou variável de ambiente.

ILzNexLogger

Quatro métodos, nenhum retorno: a implementação decide o destino. O LzNex chama LogQuery depois de cada execução com o tempo medido, e as bindings chegam cruas — formatar (ou omitir, se houver dado sensível) é responsabilidade de quem implementa.

procedure LogQuery(const ASQL: string; const ABindings: TLzNexBindings; const AElapsedMs: Int64)Uma execução concluída: SQL com os ? no lugar, os binds e o tempo em milissegundos.
procedure LogError(const ASQL: string; const AError: string)Falha. O SQL pode vir vazio quando o erro não pertence a um comando — é o caso do rollback automático no destrutor da transação.
procedure LogWarning(const AMessage: string)Aviso. O migrator usa este canal para alertar sobre commit implícito de DDL.
procedure LogInfo(const AMessage: string)Informativo. É por onde migrations e seeds anunciam o que estão rodando.

TLzNexConsoleLogger já implementa os quatro escrevendo em Output com timestamp, e aceita desligar só o log de query no construtor.

Defaults

Valores aplicados no construtor da config, antes de qualquer setter. Estão em LzNex.Config.

ConstanteValorO que define
LZNEX_DEFAULT_PORT3306Porta inicial. Em PostgreSQL você precisa trocar para 5432.
LZNEX_DEFAULT_CHARSET'utf8mb4'Charset da conexão, enviado ao Zeos como codepage.
LZNEX_DEFAULT_POOL_MIN2Conexões abertas já na construção do pool.
LZNEX_DEFAULT_POOL_MAX10Teto de conexões vivas.
LZNEX_DEFAULT_ACQUIRE_TIMEOUT30000Milissegundos que Acquire espera por uma conexão livre antes de levantar.
LZNEX_DEFAULT_MIGRATIONS_DIR'database/migrations'Diretório das migrations em arquivo .sql.
LZNEX_DEFAULT_SEEDS_DIR'database/seeds'Diretório dos seeds.
LZNEX_DEFAULT_ENV'development'Ambiente usado ao ler o JSON quando nem o argumento nem LZNEX_ENV nem a chave default dizem qual é.
LZNEX_ENV_PREFIX'LZNEX_'Prefixo das variáveis de ambiente que sobrescrevem a config (LZNEX_HOST, LZNEX_DATABASE, …).

A tabela de migrations não aparece na lista porque o default vem de LzNex.Types: LZNEX_MIGRATIONS_TABLE = 'migrations', e a tabela de lock é esse nome mais '_lock'. Para como a config é carregada de JSON e sobrescrita por ambiente, veja configuração.
